# Windows 版

在本目录双击 `安装依赖.bat`，随后双击 `启动工作台.bat`。运行数据保存在本机 `data/`，不包含在 Git 仓库中。

# 物联网测试工程自动化平台

本机入口：http://127.0.0.1:18768/ 。部署入口：/deployment 。

## 首次安装

Windows 首次使用先安装 Python，再双击“安装依赖.bat”；完成后启动工作台。详细步骤见 [交付说明](交付说明.md)。

## 操作流程

1. 创建或导入设备池，绑定平台业务设备。
2. 从设备池或已有轮次新建测试轮次，预览并确认设备清单。
3. 按四步流程配置测点模板、采集周期、告警模拟规则和转发参数，准备设备并生成工程包。
4. 点击“部署本轮”，设置目标网关、运行时长及需要切换的上一轮。
5. 完成环境预检后部署，在正式采样窗口查询平台遥测，并填写人工测量指标与验收记录。

## 设备池与轮次

- 每轮保存设备池版本、设备 ID 清单和来源轮次。支持输入目标设备总数，按来源比例建议分配，遵守库存和 BMS 整组约束；预览展示实际数量与差额。
- 复制轮次可沿用历史设备池快照，或选择最新设备池；预览列出设备增减及凭据变化数量，确认时再次检查版本。
- 轮次设备数量固定；调整数量时新建下一轮。点数、周期、模板与转发参数可修改后重新生成。
- 从小规模轮次新建下一轮，仍可选择来源设备池的全部设备。
- BMS、GROUPBMS、CELL 按确认的组合选择。
- 设备池凭据按平台设备 ID 刷新，包含已绑定通道设备；全部读取成功后提交新版本，已有轮次保留原凭据快照。

## 模板与转发

- 点击“查询并绑定已有设备”后，查询成功或失败均可继续生成。失败时点击下一步，按设备名称填入缺失的 MQTT Client ID、用户名和密码；已绑定设备保留真实凭据。任务仍在运行时需等待结束。
- 在第 4 步“计算并校验”后“生成工程包”。历史记录中按工程名称下载 ZIP；ZIP 根目录的 `summary.md` 汇总生成结果，各子工程目录只放 `tb_gateway.json`。ZIP 还包含 `validation.json` 和 `asset-device-templates/` 下的资产、设备、关系 CSV 与导入说明。
- CSV 列结构参考“资产设备”示例，数量和名称来自当前工程。电站 ID、地址、容量等现场属性需补充，关系按配置分配并需核对。模板凭据不代表平台已有该设备，须先导入并核对后上报；缺少真实平台设备 ID 时遥测核验记为未查明。

- 储能工程支持本机 XML、BMS CSV 模板及每页 100 条测点预览。每批生成固定模板快照。
- PCS、BMS 各支持一条告警测点模拟规则，按描述精确匹配；覆盖生成类型及周期，不创建平台告警规则。
- 直连使用业务设备自身 MQTT 凭据。
- 共享模式使用独立通道设备，如 jd-pcsz1。第 3 步可查询绑定或补建，已有设备凭据不改写。
- 共享设备名称使用实际平台绑定名称；通道设备不计入业务设备总数。
- 微电网保留独立模拟点配置和直连模式。

## 部署与验收

- 执行方式可选“正式部署”或“限时验证”。正式部署将生成工程安装到 `/root/gateway/thingsboard_gateway/config/<工程名>/`，执行 `systemctl stop sprixin-gateway` 后切换目录，再执行 `systemctl start sprixin-gateway`；工程在验收观察时长结束后继续保留。上传暂存目录在配置目录内，成功后删除，不创建 `/root/gateway/workbench-validation-*`。
- 限时验证继续使用 `/root/gateway/workbench-validation-<任务ID>` 保存远端脚本、状态及回滚材料，到时归档本轮工程。已有此类目录属于限时验证记录，正式部署不会自动删除它们。
- 支持整个生成批次；测试轮次必须部署全部子工程。
- 总运行时长为 10 至 604800 秒，默认 300 秒。可设置预热时间；正式采样时间为总时长减预热，至少 10 秒。预热数据不计入遥测核验。
- 可选择同一网关上一轮记录，或手动指定旧工程目录。预检、启动前及远端执行时检查配置和客户端冲突。
- 切换失败尝试回滚旧配置；限时验证成功运行后到时归档本轮，不自动启动上一轮。正式部署成功后保留本轮工程，并清理被明确替换的旧目录。
- 配置被外部修改时保留现场，进入人工恢复状态。
- 预检列出现有、停用、保留、新增工程和切换后的设备配置条目数。保留工程包含本轮同名设备时阻止切换；保留其他工程需要明确确认。启动前及远端加锁后再次核对全量配置摘要，变更后须重新预检。
- 准备部署时固定生成批次、项目版本、设备清单、配置摘要、预热/采样时长和验收阈值。报告保留执行清单 ID、遥测查询历史和人工验收修改历史。
- 点击“只读核验本轮遥测”，输入目标平台租户管理员凭据，在本轮正式采样时间范围内逐台查询配置测点。任一配置测点有数据即计为已上报；缺失和查询失败分别统计。后台最多四个并发查询，凭据只在该次查询进程内使用。
- 运行中查询只覆盖当前已发生的窗口，完整验收应在运行结束后再次核验；提前停止、查询失败或必填阈值缺少测量值时，结论为证据不完整。
- 支持最低上报设备比例及可选 MQTT 连接数、上报速率、P95 延迟、丢失率、错误率阈值。除上报设备比例外，其余指标由人工测量录入，并在说明中记录统计口径和采样窗口。
- 查询依据平台存储时间戳，需要网关与平台时钟一致；存在遥测不代表所有测点完整，也不能证明数据仅来自本轮网关。验收阈值通过不自动设置 `platformVerified`。

## 运行与数据

使用“启动工作台.bat”和“停止工作台.bat”，或 start.ps1 / stop.ps1。代码更新后重启工作台并刷新页面。

本地 JSON 保存于 data；凭据由 Windows DPAPI 加密，绑定原 Windows 用户。历史工程及生成包保留原版本。下载的网关工程包含运行凭据。
回收站支持永久删除本地工程及其关联任务、生成包和未被其他工程引用的凭据；运行中的任务或被其他轮次依赖的工程会阻止删除。此操作不删除云平台或网关服务器上的资源。

### 迁移到 macOS

在原 Windows 账号下运行 `python scripts/create_macos_bundle.py` 可导出包含现有 `data/` 的加密迁移包，生成结果位于 `dist/mac-migration-*/`。将整个结果目录复制到 Mac，在 Mac 上执行 `bash install_macos_bundle.sh`，再按目录内 `README.md` 安装依赖和启动。迁移密钥单独保存为 `migration-key.bin`；丢失后无法读取迁移数据。原 Windows 数据不会被改写。macOS 运行时新凭据使用 AES-GCM，Windows 原有 DPAPI 文件须经迁移工具转换。

## 离线测试

Windows：python -m unittest discover -s tests -v

其他系统：python tests/run_portable.py（测试进程使用内存凭据替代 DPAPI）。

业务流程改动使用临时合成数据和模拟平台/SSH 进行离线回归。真实平台 API 兼容性、网关执行及 Windows DPAPI 需要在目标环境验收。

遥测接口依据 [ThingsBoard REST API](https://thingsboard.io/docs/paas/eu/reference/rest-api/) 的时间范围查询；平台定制版本若不兼容会记为查询失败，不会计为设备缺失。
